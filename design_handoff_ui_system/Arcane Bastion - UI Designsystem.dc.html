ARCANE BASTION · UI-SYSTEM v1

OBSIDIAN & MESSING

Ein Designsystem für Godot 4 — Tokens, Komponenten, HUD-Layout und eine Umsetzungsreihenfolge, die nach jeder Phase spielbar bleibt.

Kernentscheidung vorab: Pergament raus, dunkler Stein rein. Dein stärkstes Element existiert schon — der goldene Titel auf Schwarz im Hauptmenü. Alles andere leitet sich davon ab.

01

VISUELLE DIAGNOSE

Die drei Systemfehler zuerst — sie erklären ~80 % des „zusammengestückelt“-Eindrucks. Danach pro Screen. P1 = größte Wirkung pro Aufwand.

SYSTEMFEHLER 1 · P1
Zwei Materialien

Beiges, ausgefranstes Pergament (Menüs, Inventar, Fahrplan, Synergien) und reines #000000-Panel (Turm-Info). Das sieht aus wie zwei Spiele in einem Build. Ein Panel-Material, überall.

SYSTEMFEHLER 2 · P1
Mint-Button ohne Herkunft

Das Türkis der Buttons kommt in keiner anderen Ebene vor — nicht im Gold, nicht in den Tiles, nicht in den Sprites. Mit hellem Außenrand + dunklem Innenrand + Schlagschatten wirkt es wie ein Engine-Default. Buttons sind dein häufigstes Element; sie definieren die Wahrnehmung.

SYSTEMFEHLER 3 · P1
Elemente sind unsichtbar

Elementmagie ist die Kernmechanik, aber im Shop, im HUD und auf Turmkarten trägt kein Pixel Elementfarbe. Gleichzeitig streuen Charakterkarten sechs beliebige Titelfarben. Farbe ist verschenkt, wo sie Bedeutung hätte, und verstreut, wo sie keine hat.

02

ART DIRECTION

Kalter Obsidianstein mit Messingbeschlag als neutrale Fassung — alle Farbe gehört den acht Elementen.
VIBE 1
Arkanes Observatorium

Dunkler Stein, Messinginstrumente, Kristalle in Halterungen. Präzise, gebaut, kühl — die UI ist ein Apparat, kein Buch.

VIBE 2
Emailliertes Metallschild

Harte 2-px-Kanten, flache Farbflächen, kein Gradient, kein Blur. Wie eine gestanzte Tafel — passt exakt zur Pixelkante deiner Sprites.

VIBE 3
Elementglas auf Schiefer

Referenzen im Geiste von Into the Breach (Klarheit, harte Panels), Slay the Spire (Rarity-/Farbcodierung), Hades-Menüs (Gold als Prestige, nicht als Chrom).

DIE DREI REGELN
  1. Ein Material. Jedes Panel im Spiel ist derselbe dunkle Stein mit 2 px Messingrahmen. Kein Pergament, kein Türkis, keine ausgefransten Kanten, keine Bandtitel-Sprites.
  2. Gold ist knapp. Messing markiert nur: Fokus/Hover, Währung, Legendary, den einen Panel-Rahmen. Nie Flächenfüllung, nie Buttontext auf Gold ohne Grund. Wird Gold Standard-Chrom, ist es keine Auszeichnung mehr.
  3. Farbe = Bedeutung. Ein Farbton darf nur auftreten, wenn er Element, Rarity oder Status (Erfolg/Warnung/Gefahr) bedeutet. Dekorfarbe existiert nicht.

KANTEN, TIEFE, GLOW

Schatten: nur hart, nie weich. shadow_size 0, stattdessen 4-px-Offset-Rechteck in #060810 @ 55 % hinter Overlays. Godot: shadow_color = Color("#06081080"); shadow_offset = Vector2(4,4).
Glow: kein Blur-Glow in der UI. „Leuchten“ = 2-px-Rahmen in Element-/Akzentfarbe + 18 %-Flächenfüllung. Echter Bloom bleibt dem WorldEnvironment für Projektile vorbehalten.
Panel-Kantenprofil (der Messingbeschlag, ein StyleBox für alles): 2 px #C79A3C außen, 1 px #6B5522 innen, Fläche #141A24.

ui_theme.gd

Autoload. Alle Farben als Konstanten, StyleBoxen als Factory-Funktionen — damit du nie wieder eine Farbe im Editor per Hand setzt.

extends Node
# ═══ ui_theme.gd · Autoload "UI" ═══════════════════════════════

# ── Ebenen ────────────────────────────────────────────────────
const BG_0        := Color("0A0D13")   # Screen-Backdrop
const BG_1        := Color("141A24")   # Panel
const BG_2        := Color("1E2632")   # Sektion / Row / Button
const BG_3        := Color("2A3442")   # Slot / Track / Well
const SCRIM       := Color("060810B8") # 72 % über Spielfeld

# ── Rahmen ────────────────────────────────────────────────────
const BORDER_BRASS  := Color("C79A3C")
const BORDER_SOFT   := Color("3A4658")
const BORDER_SHADE  := Color("0A0D13")
const BORDER_FOCUS  := Color("E0B44E")
const BRASS_INNER   := Color("6B5522")

# ── Text ──────────────────────────────────────────────────────
const TEXT_PRIMARY   := Color("EDE6D6")
const TEXT_SECOND    := Color("9EAAB9")
const TEXT_DISABLED  := Color("5A6675")
const TEXT_ON_ACCENT := Color("10141B")

# ── Semantik ──────────────────────────────────────────────────
const ACCENT       := Color("E0B44E")
const ACCENT_HOVER := Color("F2CB6E")
const ACCENT_PRESS := Color("B98E33")
const SUCCESS      := Color("5FBF7A")
const WARNING      := Color("E8963C")
const DANGER       := Color("E0524B")

# ── Elemente ──────────────────────────────────────────────────
const ELEMENT := {
    "feuer":  Color("FF7A45"),
    "wasser": Color("3E9BE8"),
    "erde":   Color("B5854F"),
    "luft":   Color("B9B6EE"),
    "eis":    Color("79E1E6"),
    "lava":   Color("E24545"),
    "natur":  Color("67CC63"),
    "dampf":  Color("9BB6C2"),
    "neutral":Color("9EAAB9"),
}
func el(id: String) -> Color:
    return ELEMENT.get(id, ELEMENT["neutral"])
func el_fill(id: String) -> Color:   # 18 % Flächenfüllung
    var c := el(id); c.a = 0.18; return c

# ── Rarity ────────────────────────────────────────────────────
const RARITY := {
    0: Color("9EAAB9"), # Common
    1: Color("67CC63"), # Uncommon
    2: Color("3E9BE8"), # Rare
    3: Color("B36BE8"), # Epic
    4: Color("E0B44E"), # Legendary
}

# ── Typo (px @1920×1080) ──────────────────────────────────────
const FS_DISPLAY := 48
const FS_TITLE   := 32
const FS_SECTION := 24
const FS_BODY    := 20
const FS_MICRO   := 16

# ── Spacing ───────────────────────────────────────────────────
const SP_1 := 4
const SP_2 := 8
const SP_3 := 12
const SP_4 := 16
const SP_5 := 24
const SP_6 := 32
const SP_7 := 48

# ── StyleBox-Fabrik ───────────────────────────────────────────
func _box(fill: Color, border: Color, w: int, pad: int) -> StyleBoxFlat:
    var s := StyleBoxFlat.new()
    s.bg_color = fill
    s.set_border_width_all(w)
    s.border_color = border
    s.set_corner_radius_all(0)          # nie runden
    s.content_margin_left = pad
    s.content_margin_right = pad
    s.content_margin_top = pad
    s.content_margin_bottom = pad
    s.anti_aliasing = false
    return s

func panel() -> StyleBoxFlat:
    var s := _box(BG_1, BORDER_BRASS, 2, SP_5)
    s.shadow_color = Color("06081080")
    s.shadow_size = 0
    s.shadow_offset = Vector2(4, 4)
    return s

func section() -> StyleBoxFlat:    return _box(BG_2, BORDER_SOFT, 1, SP_4)
func slot() -> StyleBoxFlat:       return _box(BG_3, BORDER_SOFT, 2, SP_1)
func slot_rarity(r: int) -> StyleBoxFlat: return _box(BG_3, RARITY[r], 2, SP_1)

func btn_primary(state := "normal") -> StyleBoxFlat:
    var fill := BG_2
    var border := BORDER_BRASS
    match state:
        "hover":    border = ACCENT_HOVER
        "pressed":  fill = ACCENT_PRESS; border = ACCENT_PRESS
        "disabled": fill = BG_1; border = BORDER_SOFT
    var s := _box(fill, border, 2, SP_3)
    s.content_margin_left = SP_5
    s.content_margin_right = SP_5
    return s

func btn_secondary(state := "normal") -> StyleBoxFlat:
    var border := BORDER_SOFT
    if state == "hover": border = BORDER_FOCUS
    var s := _box(Color(0, 0, 0, 0), border, 2, SP_3)
    s.content_margin_left = SP_5
    s.content_margin_right = SP_5
    if state == "pressed": s.bg_color = BG_2
    return s

func btn_danger(state := "normal") -> StyleBoxFlat:
    var s := _box(BG_2, DANGER, 2, SP_3)
    if state == "hover":   s.bg_color = Color("3A1F1F")
    if state == "pressed": s.bg_color = DANGER
    s.content_margin_left = SP_5
    s.content_margin_right = SP_5
    return s

func element_card(id: String) -> StyleBoxFlat:
    var s := _box(BG_2, BORDER_SOFT, 2, SP_4)
    s.border_width_left = 3
    s.border_color = el(id)     # Godot: pro-Kante-Farbe via zweitem Box-Layer
    return s

func bar(track: bool, tint: Color) -> StyleBoxFlat:
    return _box(BG_3, BORDER_SHADE, 1, 0) if track else _box(tint, tint, 0, 0)
Anwendung: ein Theme-Resource baut du einmal in _ready() aus diesen Boxen (theme.set_stylebox("normal","Button",UI.btn_primary()) usw.) und weist es der Root-Control zu — alles darunter erbt. Damit ist Phase 1 ein reiner Autoload-Job ohne Szenenumbau.

08

UMSETZUNGSREIHENFOLGE

Jede Phase ist ein abgeschlossener Commit; nach jeder Phase ist das Spiel spielbar und sichtbar besser. Keine Phase braucht neue Assets.

PHASE 1
TOKENS
ui_theme.gd als Autoload anlegen, ein globales Theme daraus bauen und der Root-Control zuweisen. Pixel Operator einbinden, alle Font-Overrides in Szenen löschen, alle corner_radius auf 0, Pergament-Texturen und Mint-StyleBoxen entfernen. Noch kein Layout anfassen.
Ergebnis: alles ist dunkel, konsistent und lesbar — mit den alten Positionen.
~1 TAG
GRÖSSTER SPRUNG
PHASE 2
KONTRAST + HIERARCHIE
Typo-Skala durchsetzen (nur 5 Größen), jede Panel-Padding auf 24, Button-Rollen vergeben (genau ein Primär pro Panel, Danger nur als Umriss), Zebra-Zeilen auf BG_2 drehen, Sekundärtext auf #9EAAB9. Icons in HBox neben das Label (Pause-Bug).
Ergebnis: Synergien und Fahrplan sind erstmals vollständig lesbar.
~1–2 TAGE
PHASE 3
ELEMENT- & RARITY-CODIERUNG
UI.el() überall anschließen: Turmkarten, Turm-Info-Header, Ability-Cooldowns, Synergiezeilen, Wave-Element. Item-Slots bekommen Rarity-Rahmen, Tooltip-Header Rarity-Farbe.
Ergebnis: das Spiel erklärt sich selbst — Farbe trägt Mechanik.
~2 TAGE
PHASE 4
HUD-UMBAU
Topbar + Bottombar nach Wireframe, freistehende Labels auflösen, Ressourcen-Pod, Turm-Info rechts andocken, Meta-Anzeigen ins [U]-Overlay verschieben. Danach 1280×720 prüfen.
Ergebnis: freies Spielfeld, ruhige Ränder.
~2–3 TAGE
PHASE 5
POLISH
Scrim + 4-px-Hartschatten für Overlays, 120-ms-Tooltip-Delay, Zahlen-Flash bei Ressourcenänderung, Pressed-2-px-Offset, Panel-Einblendung 80 ms ohne Skalierung, Hauptmenü-Atmosphäre (Elementpartikel im Hintergrund, Titel bleibt).
Ergebnis: fühlt sich fertig an.
laufend
Wenn du nur einen Tag hast: Phase 1 plus zwei Dinge aus Phase 2 — Panel-Padding auf 24 und genau ein Primär-Button pro Panel. Das ist der Unterschied zwischen „Hobbyprojekt“ und „sieht gekauft aus“.
